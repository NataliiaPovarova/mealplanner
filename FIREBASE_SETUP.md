# Настройка Firebase

Приложение работает и без Firebase — тогда доступен только базовый каталог рецептов,
без аккаунтов и личных данных. Эта инструкция включает аккаунты.

Всё, что описано ниже, укладывается в бесплатный тариф Spark: карта не нужна,
проект не «засыпает» от простоя.

## 1. Установить зависимость

```
npm install
```

`firebase` уже добавлен в `package.json`.

## 2. Создать проект в консоли

1. Открыть [console.firebase.google.com](https://console.firebase.google.com/) и создать проект.
   Google Analytics можно отключить — он не используется.
2. Внутри проекта нажать на иконку веба (`</>`) и зарегистрировать веб-приложение.
   Firebase Hosting подключать не нужно, приложение продолжает жить на Vercel.
3. Скопировать значения из показанного блока `firebaseConfig`.

## 3. Включить вход по почте и паролю

Authentication находится в левом меню консоли, в разделе Build («Создание»).
Если вы сейчас в Project settings — сначала вернитесь в проект через Project
Overview вверху слева.

При первом заходе Authentication показывает приветственный экран: нужно нажать
**Get started**, иначе вкладка Sign-in method не появится.

Дальше: Sign-in method → Email/Password → включить верхний переключатель → Save.

Второй переключатель в той же карточке, Email link (passwordless sign-in),
включать не нужно.

## 4. Создать базу Firestore

Firestore Database (там же, в разделе Build) → Create database.

В мастере три выбора, и два из них необратимы:

- **Database ID** — оставить `(default)`. Бесплатная квота действует только на
  первую базу проекта, дополнительные базы платные.
- **Location** — ближайший к пользователям регион, например `eur3`.
  **Сменить его потом нельзя**, только пересоздавать базу.
- **Режим правил** — выбрать Production (Locked) mode. Тестовый режим оставляет
  базу открытой всему интернету на 30 дней, а правила мы публикуем следующим шагом.

Если предложат выбор между обычным Firestore и версией с совместимостью MongoDB —
нужен **обычный (native) Firestore**: приложение использует штатный Firestore SDK.

## 5. Применить правила безопасности

Firestore Database → Rules → вставить содержимое [`firestore.rules`](firestore.rules) → Publish.

Это главный защитный контур: он разрешает читать и писать только внутри
`users/{uid}`, где `uid` совпадает с вошедшим пользователем. Без этого шага
заблокированный режим из шага 4 не пустит в базу даже вошедшего пользователя.

## 6. Прописать переменные окружения

Локально: скопировать `.env.example` в `.env` и заполнить значениями из шага 2.

На Vercel: Project → Settings → Environments → открыть **Production** →
Environment Variables. Отдельного пункта «Environment Variables» в боковом меню
нет, переменные лежат внутри окружения.

Там же можно вставить содержимое `.env` целиком, не набирая шесть пар вручную.
Отметить оба окружения, Production и Preview: иначе превью-сборки с веток
останутся без Firebase.

Помечать их как Sensitive не нужно. Vite подставляет любую переменную с
префиксом `VITE_` прямо в код при сборке, так что в браузер они попадают в
любом случае — от этого и защищают правила Firestore из шага 5, а не секретность
ключа.

После добавления нужен новый деплой: уже собранные деплои переменные не
подхватят.

## 7. Разрешить домен

Authentication → Settings → Authorized domains → добавить `mealplanner-three-coral.vercel.app`.

`localhost` там уже есть по умолчанию. Без этого шага вход работает локально,
но в проде отваливается с `auth/unauthorized-domain`.

## Про публичность ключей

`VITE_FIREBASE_API_KEY` попадает в бандл и виден любому — так устроена платформа.
Это идентификатор проекта, а не секрет: доступ к данным определяют правила из
шага 5 и список доменов из шага 7. Настоящие секреты (service account,
приватные ключи) в этом репозитории не нужны вообще.

## Про бэкапы

На бесплатном тарифе автоматических бэкапов нет. В приложении есть кнопка
«Выгрузить мои данные» — она сохраняет рецепты, продукты, настройки и план
недели в JSON-файл, который можно загрузить обратно.
